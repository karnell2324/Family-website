# Family Website

A private online space for approved family members to communicate, share important updates, preserve family history, and access family learning resources.

## Project status

This project is currently in the planning and development stage. The first goal is to build a working local prototype. Deployment will happen after the prototype has been reviewed and approved.

## Purpose

The website will give the family one organized and protected place to:

- Keep in touch and share family news
- Preserve family history and photographs
- Post family events and announcements
- Share educational and family learning content
- Control who can view and contribute content

## Planned features

- Private access for approved family members
- Secure sign-in and sign-out
- Administrator-managed accounts
- Family news, history, photographs, learning, and events pages
- Posting only on approved pages
- Required fields for post submissions
- Administrator review before submitted posts become visible
- Clear validation and error messages
- Navigation that works on phone and desktop screens

## User roles

### Family members

Approved family members will be able to sign in, view permitted family content, and submit posts where posting is allowed.

### Administrators

Karnell Holmes and Bahaiz are the website administrators. Administrators will manage account access, review submitted posts, and approve, reject, edit, or remove content.

## Content approval process

1. An approved member signs in.
2. The member submits a post on an allowed page.
3. The website checks that all required information is included.
4. The post remains hidden while it is reviewed.
5. An administrator approves, rejects, edits, or removes the post.
6. An approved post appears on the correct page.

## Privacy and security goals

- Private pages must require an approved account.
- Passwords must never be stored as readable plain text.
- Members must not be able to give themselves administrator access.
- Uploaded files must be limited by approved file type and size.
- The deployed website must use HTTPS.
- A backup and recovery plan must be selected before permanent family content is stored.

## Technology

The exact technology stack will be documented as development begins. The initial interface may use HTML, CSS, and JavaScript, with a database and secure server-side system added for accounts, posts, approvals, and family content.
